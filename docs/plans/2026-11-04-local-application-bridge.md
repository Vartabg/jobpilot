# Local application controller (revision 2)

Baseline: `9016a369d776a9267055d13ca0e7253aaf3f7b47`, the exact v0.13.0 installed extension source. User requested a local alternative using the existing extension, continued applications and an employer-question dataset, with no further TinyFish spending.

## Scope and design

Chrome native messaging connects the extension service worker to a Python standard-library host. The host exposes an owner-only Unix socket in a private directory, not an HTTP port. The extension connects only after the user clicks Connect and stops on Disconnect. No external service, general JavaScript evaluation, arbitrary filesystem read, CDP, remote browser, payment or CAPTCHA bypass is added. Existing manual side-panel actions remain available.

The host is registered with an exact Chrome extension origin, never a wildcard; installation takes the extension ID explicitly. Executable and runtime copies live in a persistent private application directory outside Git. The socket directory is mode 0700 and socket 0600. Reject insecure/symlink directories and competing sockets; disconnect removes only the socket owned by that host. Native JSON framing is bounded (900 KiB final UTF-8 JSON in both directions; raw PDF at most 512 KiB), exact reads handle truncated messages, and request IDs correlate one serialized operation at a time. No mutation is retried after timeout/disconnect. Same-user processes are the local trust boundary. Transport logs contain no applicant data.

CLI sends JSON requests through that socket: status, tabs, open, inspect, details, resume, answer, prepare-submit, submit, receipt. Open accepts only a supported HTTPS ATS job URL with nonempty stable job identity. Per-job commands require an explicit tab ID and expected job URL. Only Greenhouse, Lever and Ashby top-document application forms are supported initially; Workday remains available through the existing manual UI, since its multistep flow needs a separate contract. URLs, pending navigations, tab IDs and Chrome document IDs are checked before actions. Redirects/embedded or ambiguous forms fail closed. No automatic capture of unrelated tabs; tabs returns minimal metadata for supported ATS tabs only.

The new local-actions module injects existing content.js and new local-content.js in the isolated world. Existing conservative details/resume behavior is reused. Local details strips disclosure_preferences; personal/demographic decisions use only the single-question gate. The existing runner receives an internal localGuard closure that rechecks the bound scope node and control identities/labels/choices at every existing mutation guard, including after asynchronous waits; changes abort for reinspection. Its own field writes may advance values, but form replacement and conditional-control changes stop further writes. Every mutation requires a fresh inspected snapshot of the same document/form. Snapshots contain an opaque random ID and private digest of control identities, labels, choices and current values; applicant values never appear in public inventory. DOM replacement, changed choices/answers or job navigation invalidates the snapshot. Snapshots expire after five minutes, and mutation consumes the snapshot even on failure. New inspection is required afterward.

Question inventory returns exact labels (bounded, no truncation claimed as full), visible choices, requiredness, type and native constraints, plus source URL, timestamp, provider, document identity and evidence method. It excludes applicant answers and contact values. Fixed label nodes are preferred over aria-labels that may contain selected answers; unsafe/ambiguous labels are held. Oversized inventory returns an explicit error rather than silently partial text. Only application controls inside one visible form are exported; ambiguous/no form returns a diagnostic rather than unrelated page data. Radio groups and native/custom controls are represented once. Employer question data can be exported locally as JSON; CLI output can be saved into the private job-search ledger. Existing captured posting description remains the source for job requirements.

Answer accepts a single question ID, explicit value and optional replacement flag; no inferred answers. Native text/select/radio/checkbox and unambiguous accessible custom choice controls are supported. Existing answers are preserved unless replacement is explicit. Consent, legal and demographic controls require a separate `explicitPersonalDecision: true` per answer. Unsupported/ambiguous controls return a hold. Existing details DENY rules remain intact. Profile JSON and PDF must be explicitly provided by the caller, never guessed from a saved legacy profile.

Submit is an explicit new capability authorized by the user's application task. prepare-submit requires a unique visible application submit control, no missing required answers/native validation errors, no visible CAPTCHA/security challenge and accepted résumé evidence when a résumé is required. It returns a short-lived one-use nonce, the exact job URL and button label. submit requires that nonce plus `confirm: true`, unchanged snapshot, and repeats every guard immediately before one click. It never accepts terms or solves a challenge. Consume the nonce before the click, never retry a click, and report `attempted` rather than success. Duplicate prepare/submit in the same document after an attempted submission is rejected; inspect/receipt remain available. Receipt recognizes only narrow visible provider confirmation phrases after the application form disappears; no receipt means unknown, not submitted. The external canonical tracker is updated only by the coordinator after exact employer receipt evidence. The worker durably records the attempted job identity before dispatching the single click, using chrome.storage.local; disconnect/reload never clears it. The worker also verifies and consumes its known preparation nonce before recording the attempt. Unknown attempts require external reconciliation; no automatic clear/retry is exposed.

## Files and ownership

- New extension/local-content.js, local-actions.js, local-bridge.js and focused tests.
- background.js imports bridge setup; sidepanel.html adds compact Connect/Disconnect and extension ID/status; sidepanel local UI module handles only trusted runtime messages. Existing style reused, no redesign.
- manifest adds nativeMessaging and version 0.14.0, packager allowlist includes new modules.
- scripts/jobpilot_local.py supplies host/install/controller using stdlib; tests/test_local_bridge.py covers transport, installation and socket failures.
- extension/LOCAL_CONTROLLER.md documents install/reload/connect, exact command contracts, privacy, unsupported cases and uncertain-submission recovery.

## Failure behavior and acceptance

No open local network port, web caller or dynamic eval. Verify exact origin installation, framing bounds/truncation, owner-only socket cleanup, concurrency/request IDs, timeout without replay, and no applicant data in host logs. Stale/wrong tab/job/document/snapshot cannot fill, attach, answer or submit. Existing answers survive details; explicit answers and personal-decision gates work. Required conditional fields are re-inspected. Test native and accessible custom controls with real Chromium fixtures, attachment acceptance, CAPTCHA and validation holds, double-click prevention, nonce expiry, ambiguous submit buttons, false-positive success text and actual receipt recognition. Inventory/export contains labels/choices/provenance but no entered applicant values. Run the existing extension regression suite and packaging tests; inspect the actual side panel render. Package source separately, preserve private seed files and existing installed directory/identity. A user Chrome Reload and Connect is a required final activation step; never claim the live bridge or submitted applications before status/receipt verifies them.
