# One core — plan (2026-09-25)

## Why

JobPilot grew into three separate apps sharing one folder: the jobs lane (CLI and
dashboard), the gigs lane (phone swipe and an iCloud table), and the Mac app, plus a
Chrome extension. Each finds, scores, stores, and shows opportunities its own way:
7 job models, 4 scorers, 5 form fillers, 4 profile formats, and 3 servers with 2
sign-in schemes. A fix in one lane never reaches the others.

A live check on 2026-09-25 showed the cost. The fresh scan's top 10 were all the same
on-site role, in cities outside the owner's allowed locations, and each one asked for
5+ years. The best real fit ranked 13th. Scoring reads only the job title, and the
location rule was not applied because the policy file was missing.

## Decisions

- **Scope:** the owner's own search comes first. The public app continues later on
  the same core, and `product/` is parked until then.
- **Language:** a Python engine. Screens stay simple web pages; a TypeScript UI can
  follow later on the same service layer.
- **Reuse the design, not the merge:** the unmerged `codex/jobpilot-application-freshness`
  stack (73 files conflict with main) already designed the opportunity ledger,
  evidence-based requirement matching, and the versioned `JobPilotService` facade.

## Architecture: ports and adapters

- **Clients** (phone swipe, CLI, one terminal dashboard, agent JSON) talk only to the
  service layer, so every screen gets the same answers.
- **Service layer:** refresh sources, assess a role, shortlist, prepare the apply kit,
  record an outcome.
- **Domain core,** pure Python with no I/O: Opportunity, Posting, Evidence, Rules, Fit,
  and append-only Events. One status vocabulary, derived from events.
- **Plug-ins** the service calls through ports: job sources (ATS APIs and gig feeds),
  a fit agent (an agent framework plus an LLM), the ledger (one SQLite file under the
  data folder), and the apply-kit renderer.

Rules: the core never imports plug-ins; tests never touch real data; every resume or
answer claim traces to recorded evidence; a person submits every application by hand.

## Phases

| Phase | What | Done when |
|---|---|---|
| 0 · Safety | Data-loss fixes, a hermetic test suite, the missing CI dependency | CI is green and the suite cannot write to `data/` |
| 1 · Foundation | One data-folder resolver, one settings schema, the opportunity ledger, stable role identity | Queue, tracker, and gig pipeline rows are imported as events |
| 2 · Pipeline | Source registry → full posting → hard rules → evidence fit (agent) → ledger | Regression cases pass: an on-site role outside allowed locations that requires 5+ years is excluded, and a remote role whose requirements match evidence ranks first |
| 3 · One service | One server and one sign-in; phone swipe, CLI, apply kit, and one terminal view run on the service | Every screen reads from the same service |
| 4 · Cleanup | Delete the duplicated fetchers, scorers, stores, servers, and fill paths | One of each piece, with import contracts checked in CI |

## Keep, park, cut

- **Keep:** gigs as one more source, phone swipe, CLI, and the apply kit (tailored
  resume and paste sheet). Merge the six terminal views into one.
- **Park:** the Mac app (`product/`), including its user-activated fill.
- **Cut from the core:** automated form filling (`form_filler`, the LinkedIn watch
  loop, the Chrome extension, the dashboard bookmarklet), per
  [APPLICATION_FLOW.md](../APPLICATION_FLOW.md), and the unused ghost and chat overlays.

## Phase 0 (this change)

- `JOBPILOT_DATA_DIR` relocates all state, and every module derives its paths from
  `config.DATA_DIR` instead of its own file location.
- `tests/conftest.py` points the suite at a throwaway folder and fails the run if the
  checkout's `data/` folder changes. Before this, every test run rewrote the real
  `settings.json`, `applications.db`, `queue.js`, and `jobpilot.log`.
- `AutonomyConfig.save` merges into `settings.json` instead of replacing it (it was
  wiping `resume_lanes`), and backs up an unreadable file first.
- `ProfileStore` keeps keys the model does not declare (`skills`, `target_titles`, and
  `domain_experience` were dropped on save), and backs up an unreadable profile before
  overwriting it.
- `pypdf` joins the dev extra, so CI can import `product/`.
